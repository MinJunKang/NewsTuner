# News Tuner

영어권 매체의 기사를 라디오 주파수처럼 맞춰 읽고, 단어를 눌러 뜻을 보고, 기사에 대해 대화하는 개인용 앱입니다.
아이폰 홈 화면에 설치되는 PWA라 개발자 계정(연 $99)이 필요 없습니다.

키는 Gemini 하나만 있으면 됩니다.

- **뉴스 수집** — Gemini 3.7 Flash + Google 검색 그라운딩
- **단어·문장 풀이** — Gemini 3.5 Flash-Lite
- **기사 토론** — Gemini 3.7 Flash

처음 쓰는 사람에게는 [사용 설명서(PDF)](public/NewsTuner-Guide-KR.pdf) 를 보내 주세요.
설치·설정·사용법이 정리되어 있습니다. `public/` 에 두어 앱과 함께 배포되므로,
설정 탭의 "설명서 열기" 로도 같은 내용이 열립니다.
영어판은 [User Guide (English)](docs/NewsTuner-Guide-EN.pdf) 이고 저장소에만 둡니다.

설명서 본문은 한국어가 `src/guide.json`, 영어가 `docs/guide.en.json` 입니다.
문구를 고친 뒤 PDF 를 다시 만들려면:

```bash
pip install fpdf2
python3 docs/build-guide.py             # 한국어 → public/
python3 docs/build-guide.py --lang en   # 영어 → docs/
```

한국어판은 앱 화면과 PDF 가 같은 JSON 을 읽으므로 그 파일만 고치면 양쪽이 함께
바뀝니다. 나눔고딕 TTF 가 필요하고, 경로는 `--font` 로 줍니다.

## 1. GitHub에 올리기

저장소는 **public**이어야 GitHub Pages가 무료입니다. 키는 코드에 없고 앱 설정 화면에서 입력받아
각자의 기기에만 저장되므로, 코드가 공개돼도 크레딧이 새지 않습니다.

```bash
cd news-tuner
git init
git add .
git commit -m "News Tuner"
git branch -M main
git remote add origin https://github.com/<아이디>/news-tuner.git
git push -u origin main
```

## 2. Pages 켜기

저장소 → **Settings** → **Pages** → Source를 **GitHub Actions**로 바꿉니다.

그러면 Actions 탭에서 배포가 돌기 시작하고, 1~2분 뒤 주소가 나옵니다.

```
https://<아이디>.github.io/news-tuner/
```

`vite.config.js`가 저장소 이름을 읽어 base 경로를 맞추므로, 저장소 이름을 바꿔도 손댈 곳이 없습니다.

이후로는 `git push` 할 때마다 자동 배포됩니다.

## 3. 아이폰에 설치

1. **사파리로** 위 주소를 엽니다 — 크롬에는 "홈 화면에 추가"가 없습니다
2. 하단 공유 버튼 → 아래로 스크롤 → **홈 화면에 추가**
3. 아이콘이 생기고, 주소창 없는 전체화면으로 실행됩니다

## 4. 키 넣기

앱을 처음 열면 **설정** 탭이 먼저 뜹니다.

aistudio.google.com 에서 키를 발급합니다. 키는 그 기기의 localStorage에만 저장되고,
한 번 넣으면 계속 유지됩니다.

### 결제 연결이 필요합니다

**뉴스 수집에는 결제가 연결된 키가 필요합니다.** Google 검색 그라운딩이 무료 티어에서는
"Not available" 이라, 무료 키로 "기사 찾기"를 누르면 429 를 받습니다.
AI Studio → Billing 에서 결제를 연결하면(Tier 1) 바로 열립니다.

| | 무료 티어 | 결제 연결(Tier 1) |
|---|---|---|
| 단어 풀이 · 대화 | 됩니다 | 됩니다 |
| **뉴스 수집(검색 그라운딩)** | **안 됩니다** | 됩니다 |

검색 그라운딩은 월 일정 횟수까지 무료이고 그 뒤로는 건당 과금입니다. 개인 사용이면
무료분을 넘길 일이 거의 없습니다. 최신 요금은
[ai.google.dev/pricing](https://ai.google.dev/pricing) 에서 확인하세요.

실제로 나가는 건 토큰 값인데, 이건 어느 경로로 기사를 만드느냐에 따라 몇 배씩
차이가 납니다. 피드가 있는 매체를 골라 전문 추출이 성공하면 한 기사가 모델 호출
**한 번**으로 끝나고 검색 그라운딩도 안 씁니다. 피드가 없어 검색 경로로 떨어지면
목록과 집필이 각각 검색을 돌리고 검색 결과가 입력에 통째로 들어가 여러 배가 되며,
목록마저 실패하면 기사를 못 얻고도 값은 나갑니다. **매체를 추가할 때 RSS 피드
유무를 먼저 확인해야 하는 이유입니다.**

집필 호출은 `thinkingLevel: "low"` 에서 생각 토큰을 거의 쓰지 않으므로, 비용을
줄이는 레버는 thinking 이 아니라 경로입니다.

본인 사용량과 청구액은 설정 탭의 **사용량 기록**에서 확인하세요. 매체별 기사 수,
글자수, 토큰, 호출 수, 전문/검색 경로 비율이 남습니다. 프로젝트의 실제 한도는
[aistudio.google.com/rate-limit](https://aistudio.google.com/rate-limit) 에서 봅니다.

## 원문 복사하는 방법

난이도에서 **원문**을 고르면 기사를 붙여넣어 읽습니다. 본문을 손으로 선택하는 게
번거로우니 기기별로 편한 방법을 정리합니다. 같은 내용이 앱 안에서도 보입니다.

### 아이폰 — 단축어로 한 번에 (권장)

한 번만 만들어 두면 그다음부터는 탭 두 번이고, 본문을 선택할 필요가 없습니다.
단축어 앱에서 새 단축어를 만들고 액션 세 개를 순서대로 넣습니다.

1. **웹페이지에서 기사 가져오기**
2. **기사 세부사항 가져오기** — 항목을 **본문**으로
3. **클립보드에 복사**

단축어 정보에서 **공유 시트에 표시**를 켭니다.

```
사파리·크롬에서 기사 → 공유 → 방금 만든 단축어
  → News Tuner 에서 "클립보드에서 가져오기" 한 번
```

사파리와 크롬 모두 같은 공유 시트를 쓰므로 그대로 동작합니다. 액션 이름은 iOS
버전마다 조금 다를 수 있습니다.

단축어를 안 만들 거라면 사파리 주소창 왼쪽 **aA** → **읽기 도구 표시**를 켜고 길게
눌러 전체 선택하세요.

### 갤럭시 · 안드로이드

안드로이드에는 단축어에 해당하는 기본 기능이 없어서, 읽기 모드를 켜고 직접
선택하는 방식이 가장 확실합니다. 광고와 메뉴가 빠져 본문만 잡힙니다.

- **크롬** — 오른쪽 위 **⋮** → **간소화된 보기**(또는 읽기 모드) → 본문을 길게 눌러
  **전체 선택** → 복사
- **삼성 인터넷** — 주소창의 **리더 모드** 아이콘을 켜고 같은 방식으로 복사

메뉴 이름은 기기와 브라우저 버전에 따라 조금 다를 수 있습니다.

### 컴퓨터

기사 본문을 클릭하고 Ctrl+A(맥은 ⌘+A) 후 복사합니다.

## 설계 메모

**원문을 긁어오지 않습니다.** Gemini가 검색으로 실제 기사를 찾은 뒤, 사실만 가져와 새로 씁니다.
저작권 문제를 피하고 난이도(A2~C1)를 조절할 수 있게 하는 선택입니다.
원문 링크와 그라운딩 출처는 기사 하단에 함께 표시됩니다.

**모델을 나눠 씁니다.** 단어 클릭은 짧고 잦으니 Flash-Lite(생각 기본값이 minimal 이라 빠릅니다),
뉴스 수집과 토론은 Flash를 씁니다. 모델명은 자주 바뀌므로 `src/api.js`의 `MODELS` 객체
한 곳에서만 고치면 전체에 적용됩니다. `api/_shared.js`의 `ALLOWED_MODELS`도 함께 고치세요.

**기사와 단어장은 기기에 남습니다.** 앱을 껐다 켜도 마지막 기사가 그대로 있습니다.

## 부록 A — Vercel 로 프록시 두기 (권장, 터미널 불필요)

프록시를 두면 세 가지가 좋아집니다. API 키가 폰이 아니라 서버 환경변수에 살고,
기사 링크가 실제로 열리는지(`/check`) 확인해 죽은 링크를 목록에서 미리 빼고,
**기사 전문을 가져와(`/extract`) 모델이 검색 발췌 조각 대신 전문을 놓고 씁니다.**
전문 모드에서는 분량이 제대로 나오고, 다른 기사가 섞일 통로가 사라지며, 검색
주입 비용이 빠져 오히려 저렴합니다. 전문을 못 가져오는 기사(유료 장벽 등)는
자동으로 기존 검색 방식으로 돌아갑니다. 이 두 기능은 Vercel 함수에만 있습니다.

`api/` 폴더에 Vercel 함수가 이미 들어 있어, 하실 일은 클릭 몇 번입니다.

1. [vercel.com](https://vercel.com) 에서 **GitHub 계정으로 가입** (카드 불필요)
2. **Add New → Project** → 이 저장소 **Import**
3. 설정은 기본값 그대로 두고 **Environment Variables** 에 두 개 추가
   - `GEMINI_KEY` — Gemini API 키
   - `SHARED_TOKEN` — **필수.** 아무 긴 문자열 (남이 내 서버를 쓰지 못하게 막는 비밀번호)
4. **Deploy** → 끝나면 `https://<프로젝트>.vercel.app` 주소가 나옵니다

`SHARED_TOKEN` 을 넣지 않으면 함수가 503 으로 거부합니다. 서버 주소는 앱에 들어
있는 공개된 값이라, 검문이 꺼지면 누구나 이 함수로 내 Gemini 크레딧을 쓸 수 있기
때문입니다. 예전에는 토큰이 없으면 그냥 통과시켰는데, 환경변수를 빠뜨리면 아무
경고 없이 열려 있었고 열린 줄도 몰랐습니다. 이제는 눈에 띄게 멈춥니다.

앱 설정에는 이렇게 넣습니다.

| 칸 | 값 |
|---|---|
| 서버 주소 | `https://<프로젝트>.vercel.app/api` ← **뒤에 /api 필수** |
| 서버 토큰 | `SHARED_TOKEN` 과 같은 값 |

`src/App.jsx` 의 `DEFAULT_SERVER` 가 서버 주소 칸의 기본값입니다. 토큰만 받은
사람이 바로 쓸 수 있게 미리 채워 두는 값이니, 자기 서버를 띄웠다면 여기도 바꾸세요.

이후에는 지금처럼 `git push` 만 하면 Vercel 이 함수까지 자동으로 다시 배포합니다.
무료(Hobby) 한도는 월 100만 호출이라 개인 사용의 수백 배 여유가 있고, Hobby 는
개인·비상업 용도 전용입니다.

매체를 추가하면 `api/_shared.js` 의 `ALLOWED_HOSTS` 도 `src/App.jsx` 의 domain 과
같게 고쳐야 합니다.

## 부록 C — 오류 기록 "바로 전송" 켜기 (구글 폼)

설정 탭의 오류 기록은 "바로 전송" 버튼으로 구글 폼에 무음 전송됩니다. 서버도
API 키도 없습니다. 폼을 새로 연결하려면 아래처럼 만듭니다.

1. [forms.google.com](https://forms.google.com) 에서 새 폼 → **장문형 질문 1개** 추가
2. 폼의 **응답 탭 → ⋮ → 새 응답에 대한 이메일 알림 받기** 켜기 ← Gmail 로 알림이 옵니다
3. 보내기 → 링크에서 `…/d/e/`**긴문자열**`/viewform` 의 긴 문자열이 `formId`
4. ⋮ → **미리 채워진 링크 받기** → 아무 값 입력 후 링크 생성 → 링크 속 `entry.`**숫자** 가 `entryId`
5. `src/App.jsx` 상단 `REPORT_FORM` 에 두 값을 채우고 push

채우면 설정 탭에 "바로 전송" 버튼이 나타나고, 기록이 폼 응답함(+시트)으로 쌓입니다.

## 부록 B — 서버가 링크 생존을 확인하는 방식

브라우저는 CORS 때문에 다른 사이트의 주소를 불러 상태 코드를 읽을 수 없습니다. 그래서
링크가 실제로 열리는지는 서버를 통해서만 확인됩니다. 서버를 두면 기사 목록을 보여주기
전에 `/check` 로 확인해서 **404 인 링크를 미리 뺍니다.**

뉴스 사이트가 데이터센터 IP를 봇으로 보고 403을 주는 일이 흔해서, **404와 410만 죽은
것으로 봅니다.** 그 외 응답이나 시간 초과는 판단을 보류하고 링크를 남깁니다. 확인하지
못한 것을 죽었다고 처리하면 멀쩡한 기사가 사라집니다.

`api/_shared.js` 의 `ALLOWED_HOSTS` 는 `src/App.jsx` 의 매체 `domain` 값과 같게 유지하세요.
매체를 추가하면 양쪽 다 고쳐야 합니다.

예전에는 Cloudflare Workers 구현이 대안으로 함께 있었는데, 거기에는 `/extract` 와 `/feed`
가 없어 피드와 전문 경로가 통째로 빠졌습니다. 같은 정책을 두 곳에 유지하는 비용만 들고
기능은 반쪽이라 지웠습니다. 서버는 **Vercel 하나**로 둡니다.
